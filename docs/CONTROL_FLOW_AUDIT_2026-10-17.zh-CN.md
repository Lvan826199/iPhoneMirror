# 有线／无线控制全流程审查（2026-10-17）

基线为 `62be537`。检查应用入口、绑定与会话所有权、桥接进程、发现与信任、DDI、
CoreDevice/RSD、HID、输入代次、剪贴板、恢复和退出清理。后续复审将工作区已有的
媒体认证/HID 恢复改动单独提取、审查并验证后纳入本轮控制修复；屏幕旋转、解码器、
采集 mux 共享和托盘等其他变更没有混入。

## 本轮确认并修复

1. **多层无线回退重复准备 USB 镜像。** Network → RemotePairing → USB 准备后的
   外层 HID 重试会再次进入同一准备流程。故障注入复现一次启动创建 **14 次 USB
   Lockdown**。现在仅在同一会话成功完成准备后记录状态；各层重试共享它，准备失败
   或取消不记录成功。实际控制仍使用无线，已连接 HID 的故障仍交给应用层重连。
2. **ready 条件使用了错误的逻辑与。** Python 在 gate 关闭但 HID 存在，或 gate 打开
   但 HID 为空时，未立即拒绝。现在两者必须同时满足，之后仍验证 sender 与 PING。
3. **应用没有验证 ready 的协议版本。** 旧版、未来版或缺少 protocol 的事件可进入
   ready。现在只接受协议 2；若携带 generation，它必须是正整数。保留早期协议 2
   未携带 generation 的兼容路径。身份、transport 和 gate 检查继续生效。
4. **旧粘贴可能跨越连接恢复。** 粘贴排队或发送组合键期间发生恢复，旧操作可能向
   新 HID 继续发送 Command/V 或空按键释放。现在入队时捕获代次；每个按键与恢复锁
   一起核对代次。恢复后终止旧操作，不重放组合键；同一代次取消仍释放已按下的键。
5. **媒体认证流失效后仍可能保持就绪。** 原接收任务忽略退出/断连，HID 能 PING
   不代表媒体认证仍有效。现在首先等待实际媒体数据，接收失败、任务结束或连续
   30 秒没有媒体数据时撤销认证门与输入就绪，并交给传输所有者重建媒体和 HID。
   首包等待最多 10 秒。该失败不会被当作“缺少可选媒体服务”而改走直接 HID。
6. **媒体认证模式缺少完整的 HID 生命周期恢复。** 原有定期刷新和行内修复只适用于
   direct 模式。现在媒体认证保持有效时也可修复同一隧道上的 HID；健康刷新遇到
   持键/触点会延后。替换 HID 明确归本会话所有，停止和取消时先释放它，再关闭媒体门。

## 全流程核对

| 环节 | 有线 | 无线 |
| --- | --- | --- |
| 应用入口 | SingleFlight 与目标绑定检查；停止与恢复等待原桥接器释放 | 相同；每设备保存目标与进程，UI 选择不转移所有权 |
| 设备发现 | USB Lockdown；采集配置下可用共存 mux；不自动修改信任 | Network Lockdown → 已保存凭据的 RemotePairing/mDNS；不把 USB 控制冒充无线 |
| 镜像准备 | Developer Mode、Cryptex/Personalized、实际 inventory、固定资源校验和总期限 | 先验证控制服务；缺少 HID 时精确匹配同一台 USB 设备准备，再重建无线快照 |
| 控制就绪 | RSD UDID → 实际 mainTouchscreen → release 报告与同连接 PING → ready | 相同；应用再验证协议、身份、transport、gate 和输入代次 |
| 输入 | 写锁、目标/所有权/代次检查，触点预算，按键与按钮状态，粘贴代次隔离 | 相同；过期数据不能进入恢复后的输入代次 |
| 恢复 | 桥接器保留活跃采集 mux；HID 修复或重建隧道；有限尝试 | 已就绪会话断线由应用退出原桥接进程后重新发现；启动阶段才尝试其他地址 |
| 退出 | 关闭 stdin、取消消费者、释放输入状态、关闭 HID/RSD/tunnel/Lockdown/mux；进程有界退出及子进程回收 | 同样清理；不创建或保留 USB 控制会话 |

结论限于当前源码和自动回归；不能承诺所有设备、系统和网络条件下无错误。
