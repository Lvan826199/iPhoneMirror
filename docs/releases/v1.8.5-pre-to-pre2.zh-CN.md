# iPhoneMirror 1.8.5-pre → 1.8.5-pre2 完整更新日志

发布日期：2026-10-09。版本性质：预览版。

对比范围：`v1.8.5-pre`（54c36cad597e995dbfb3999de42287082d22cce9）到 `v1.8.5-pre2`（5a260d7e25e040481959ff86913341e7db24b97a）。
本清单根据发布标签的实际代码差异、CHANGELOG 的新增记录及对应功能文档整理。下列修复是实现变更，不表示所有设备和网络场景都已完成实机验收。

## 一、新增首次设置助手与设置检查

- 新增首次设置助手，涵盖基础偏好、应用模式、外观、使用方式、设备配置、无线组件和画质设置。
- 支持无线投屏、有线投屏、投屏与反控等不同用途，按选择跳过不需要的功能。
- 设置助手仅首次启动自动显示；首次显示即保存进入记录，未完成也不会在每次启动时重复弹出。
- 保留应用偏好、投屏设置和开发者选项中的手动入口，保留未完成进度和已有设备档案。
- 每次手动进入先检查实际设置，再显示汇总；支持重新检查、处理缺项及重新配置全部设置。
- 按已完成、未完成、无效、不需要、未知区分结果；设备离线或检查超时不再被视为全部就绪。
- 检查 Apple 服务与驱动、USB 后端、接收组件、设备绑定、蓝牙环境、设备信任、开发者模式及所需无线同步设置。
- 新增只读驱动诊断与设备端设置检查；检查本身不安装驱动、不主动配对、不下载或挂载 DDI，也不发送控制输入。
- 可明确关闭 USB 控制、无线投屏/控制或蓝牙控制，相应检查项按“不需要”处理。
- 多设备按身份分别配置，新设备独立进入待配置列表；扫描不擅自删除旧绑定。
- 修复设置后只重新检查受影响的项目，按依赖进入下一项，不重复扫描无关硬件或逐页重放检查动画。
- 支持步骤跳过、返回、取消、关闭确认和断点保存；设置保存失败时保留当前步骤并显示错误。
- 已安装组件和已有设备绑定可直接复用；更改无线设置时按实际需要重新启动接收器。
- 保存逐设备画质偏好，包括有线显示、帧率和解码设置。
- 检查和汇总共用卡片与行控件，状态原位更新，减少阶段切换跳动；支持长列表、窗口尺寸变化及系统动画偏好。
- 设置期间暂停主窗口自动刷新，退出后恢复完整、精简或托盘模式。

## 二、新增本地自动化 API

- 在开发者工具中新增本地 Automation API，默认关闭，仅监听 `127.0.0.1`，默认端口为 17890。
- 提供设备列表、设备详情、连接与反控状态、能力和画面几何信息查询。
- 提供设备截图、点击、长按、按下/抬起、滑动、触摸路径、按键、文本输入及剪贴板读写接口。
- 提供离线 API 文档、OpenAPI 3.1 描述以及 Python、curl/PowerShell 示例。
- 使用 API Key 和细分权限；凭据采用当前 Windows 用户的 DPAPI 保护。
- 校验请求来源与 Host，限制请求速率、正文大小、路径点数、截图并发和连接数。
- 新增按设备排他的控制租约；支持续租、释放、到期回收，以及界面上的手动收回控制。
- 同一已绑定手机的 USB/AirPlay 身份共享控制所有权，多设备分别管理租约。
- API 输入与手动操作、键位映射、快捷键使用同一输入准入规则，避免互相抢占。
- 使用实际采集画面像素坐标与已有校准映射，画面尺寸、会话或校准变化后旧几何信息失效。
- 截图复用原生采集帧，编码移出 UI 线程；并发请求可共享同一编码任务。
- 桥接器新增剪贴板 RPC 能力；剪贴板读取不模拟复制键，纯写入不自动发送粘贴键。
- API 复用已建立的投屏和反控连接，不自动安装驱动、下载 DDI 或启动其他传输方式。
- 蓝牙 API 能力按实际键盘通道报告，不宣称支持绝对坐标触摸或任意 Unicode 剪贴板功能。

## 三、键盘、输入会话与重连修复

- USB/无线反控重新连接后恢复独立预览窗口的键盘路由与输入所有权。
- 自动更新 Windows 键盘钩子，修复钩子被系统静默移除后鼠标可用但键盘和快捷键失效的问题。
- 钩子恢复时同步修复按键录制和映射状态，清理漏收到的修饰键释放事件。
- 恢复时仍按住的按键保持隔离，直到实际松开，避免意外重复输入。
- 串行管理控制桥启动与停止，停止时取消尚未完成的启动，忽略旧进程的迟到输出和退出回调。
- 区分各次桥接会话的输入生命周期，旧会话的排队输入和剪贴板请求不能进入新会话。
- 修复排队输入取消、标准输入阻塞导致关闭卡住、进程复用和迟到回调问题。
- 多设备与同一物理手机的不同连接源按实际身份管理输入，避免清理操作误伤替代连接。
- 退出控制前释放触摸、键盘和待处理按钮状态；取消长手势时清理其原始会话。
- 清理尚未完全创建的 HID、媒体认证及按钮服务，保留原始失败原因。
- HID 重连保留可用的备用服务；Modern HID 缺少触摸通道时回退到 Legacy HID。
- 可选媒体会话失败时保留已经成功的直接认证路径，不把可用连接一并丢弃。
- 为媒体服务初始化与清理设置等待上限，避免反控启动或退出无限等待。
- 修复提示窗口在主窗口隐藏或已关闭时的 Owner 设置，避免错误提示与停止通知出现无效窗口关系。

## 四、有线连接、USB 后端与退出恢复

- USB 控制桥内完整打包固定版本的 x64 `libusb0` 和 `libusb-1.0` 后端 DLL。
- 构建自检实际加载两个原生 USB 后端；缺失任一后端时拒绝打包。
- 调整 PyInstaller USB 发现钩子，避免构建机上的 DLL 别名遮蔽随包提供的后端。
- 可选采集后端无法加载或 USB 发现失败时，保留 Apple 标准 USB 控制路径。
- 采集复用服务启动超时后不再报告尚未绑定的地址；取消时关闭已创建监听并结束服务循环。
- 启动期间客户端断开或取消转发时，关闭对应连接和双向转发任务；取消之后迟到的 USB 连接也会被清理。
- 部分初始化的 USB 控制接口在重试或回退前释放；设备移除导致清理失败时保留最初错误。
- 对 Lockdown 握手重试设置边界，包括无线控制所需的 USB DDI 准备，取消时关闭部分初始化的设备套接字。
- 投屏退出时先等待控制桥清理，再结束采集，并为活动设备保留有界的退出清理时间。
- USB 配置恢复助手结束后继续观察恢复窗口，避免过早判定失败。
- 必须发现对应设备的真实 USB 记录才确认恢复，不能用无线设备记录代替。
- 有线投屏结束后 Apple 管理连接仍未恢复时，尝试仅重新连接受影响手机的 USB 端口。
- 端口恢复按需要请求管理员权限，并在操作后重新验证，不在未确认前报告成功。
- 增加逐设备 USB/PnP 恢复状态日志，保留配置恢复助手的失败信息。

## 五、无线反控与设备发现

- 区分“没有发现无线广播”和“已发现地址但连接失败”，保留握手错误与配对指引。
- 重试发现的无线地址，对发现、可选配对、隧道启动和关闭设置等待上限。
- Network usbmux 初始连接被重置、失败或不可用时尝试 RemotePairing。
- Network CoreDevice 隧道就绪前失败时保留 RemotePairing 回退路径。
- 连接输入服务前核对 RSD 设备身份，避免连接到错误设备。
- 明确区分 USB 与无线控制；USB 隧道不存在时提示用户选择无线控制，不再偷偷改走 Wi-Fi 却仍显示有线。
- 无线恢复保持用户选择的传输方式，不随恢复操作切换到另一条连接路径。
- 检测无线 HID 空闲期间的连接失效，并保留失效隧道恢复能力。
- 输入服务在启动时被重置后尝试其他 HID 服务，并验证候选服务确实可用。
- 取消无线启动或清理时主动关闭套接字，保留信任、锁屏、取消及超时等具体错误。

## 六、DDI 下载、缓存、个性化与挂载

- 增加兼容版本的固定 DDI 下载来源，GitHub 元数据失败时仍可尝试镜像和本地候选。
- 下载镜像前验证清单，支持官方 `Image.dmg.trustcache` 文件名。
- Range 探测失败不再直接淘汰可用镜像；已成功完成验证下载的来源优先用于后续文件。
- 复用镜像测速结果，隔离直连请求与代理设置，避免重复探测和错误代理影响。
- 为各个下载来源设置独立尝试时限；检查部分读取，防止慢速源耗尽全部回退预算。
- 元数据查询、镜像探测和文件下载共用有界等待预算，并记录传输字节数和耗时。
- 原子发布已验证的 DDI 缓存快照，刷新时保留已有挂载正在使用的文件。
- 原子切换遇到 Windows 短暂文件共享冲突时进行有界重试，保持取消能力和旧缓存。
- 下载取消后不发布缓存；并发刷新或下载失败不会留下可误用的半成品。
- 不兼容缓存的拒绝记录按设备和系统版本隔离，并设置五分钟有效期。
- 对被拒绝缓存允许一次刷新，避免对相同内容反复下载和重试。
- 缓存创建、磁盘空间和写入权限失败显示可操作提示，不盲目重试无关镜像。
- 修复损坏的 DDI 缓存清单处理；规范候选与缓存顺序，保留本地回退来源。
- Apple 个性化签名支持取消；临时签名失败在总时限内重试。
- 为镜像服务启动、上传、挂载及验证设置等待上限，并明确报告失败阶段。
- 挂载后确认镜像实际可用；清理错误不覆盖原始失败原因。
- 桥接器运行库检查保留具体诊断信息，不再统一替换成未知错误。
- 新增四种语言的下载、缓存、签名、挂载和控制启动错误指引。

## 七、AirPlay 接收与音视频恢复

- 在现有接收器基础上选择性适配 AirPlayServer v1.2.5 的修复，保留现有旋转恢复与公共 DLL/FFmpeg ABI。
- 为 AVC 参数记录增加边界校验，防止截断或非法参数包继续进入处理流程。
- 修正底层时钟单位换算和 Windows 绝对等待期限，改善跨秒计时与超时行为。
- 校验 timing 响应，忽略空 RTP 数据包，改进音频停止时的资源清理。
- 屏幕镜像 AAC-ELD 改用 FFmpeg 原生 AAC 解码器；无效解码结果不再作为有效 PCM 发送。
- PCM 转换保留实际解码采样数量与采样率；未恢复音频包的补偿使用协商的帧长度。
- 同一发送端 TCP 连接中断后支持在 120 秒窗口内恢复，包括暂停期间的恢复。
- 正常静止画面和已连接空闲流不设无帧超时；不完整数据包读取保留三秒期限。
- 更换传输连接时清理待处理解码与时间戳状态，同时保留协商的 AES 流上下文。
- 修复中断加密载荷的 CTR 推进；连续非法解密帧会结束旧流，使新 SETUP 能重新建立状态。
- 同一流 ID 的重复 SETUP 保留 CTR 并返回现有端口；新流 ID 会先回收旧线程再安装密钥与套接字。
- 完整保留音频和镜像远端的 IPv4/IPv6 地址。
- 次级媒体端口绑定到实际 AirPlay 控制连接所在的本地网卡，降低代理、VPN 或虚拟路由造成的接口错配。
- 新增发送端暂停、重连和画面几何状态传递；主机与核心 IPC 升至版本 8。
- 发送端几何信息独立保存，在新解码帧到达前保留最后画面和真实解码尺寸。
- 保持新增预览与已有静止画面的显示状态，音频更新不会覆盖暂停或重连状态。
- 暂停及重连状态提供四种语言的本地化提示。
- 构建脚本重新应用并验证接收器补丁与能力标记，记录构建来源、运行库哈希和许可证信息。
- 将 AirPlay `BUILD.json` 来源记录纳入正式发布文件校验。

## 八、UxPlay 组件安装与更新

- 显式安装时查询最新公开应用 Release，包括预览版；排除草稿和独立组件 Release。
- 校验该 Release 的 UxPlay 附件摘要或 SHA256SUMS，不再单靠旧的内嵌下载描述决定安装来源。
- 应用要求新组件版本时，旧组件不能掩盖升级需求；缺少配套组件时拒绝静默下载更旧版本。
- 已验证的新组件可离线使用，不在每次启动时自动联网检查。
- 保留已校验的组件 ZIP；运行库文件损坏时可由本地 ZIP 修复，ZIP 损坏时重新下载并验证。
- 从已验证的 ZIP 生成逐文件记录，安装收据采用当前用户 DPAPI 保护，不信任可编辑的旧明文元数据。
- 强化路径穿越、重复条目、符号链接、超大条目、文件哈希及并发安装校验。
- 取消或安装失败不会留下已就绪收据，保留原有可用组件。
- 发布与应用版本匹配的 `iPhoneMirror-UxPlay-v1.8.5-pre2-win-x64.zip`，解决本地 pre2 要求高于公开 pre 组件导致的安装阻塞。

## 九、打包、版本与维护

- 应用和驱动统一使用产品版本 `1.8.5-pre2`、程序集及文件版本 `1.8.5.0`。
- 显式指定构建版本时同时设置数值程序集与文件版本，避免版本信息分离。
- 安装包和便携版包含自动化 API 所需的 ASP.NET 运行库，无需额外安装 Hosting Bundle。
- 保留完整媒体输出 FFmpeg 运行库，以兼容性优先于包体大小。
- 更新发布流程、Windows 构建流程、USB 配方与运行库验证、AirPlay 上游测试及多语言检查。
- 补齐反控链路、两设备场景、首次设置、DDI、USB 恢复、API 和 AirPlay 构建来源文档。
- 修正测试程序通过 dotnet 宿主启动子进程时的调用方式，并稳定部分桌面测试初始化。

## 十、验证及已知限制

- 本次构建通过 16 项原生测试、396 项 Python 测试、应用逻辑测试、驱动测试及运行库检查。
- 设置助手专项回归正常退出，覆盖首次显示记录、未完成后不自动重开、手动入口、368 组布局及多设备流程。
- 自动化 API 集成和已有输入、剪贴板、采集恢复等运行时断言通过。
- 完整桌面运行时测试打印断言通过后，进程退出出现 `0xC0000409`；Windows 记录指向 AMD `amdxx64.dll` 32.0.21032.8002。因此不应表述为完整运行时测试进程正常通过。
- 最终 EXE、ZIP、UxPlay 附件的大小和 SHA-256 与 GitHub 上传结果一致；便携 ZIP 的 881 个文件与发布目录逐一匹配。
- API 返回输入已分发不等于 iPhone 已执行；文本粘贴可能需要在手机上确认系统授权。
- 未新增自适应音频时钟补偿；跨设备、网络、画质及显卡场景仍需实际使用验证。
- 预览版通知仍由用户的更新偏好决定，本次没有强制所有旧客户端开启预览版通知。
