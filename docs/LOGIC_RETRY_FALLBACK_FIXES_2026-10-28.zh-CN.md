# 逻辑审查修复记录（2026-10-28）

对应上轮逻辑审查的全部 10 项问题：2 项 P1、8 项 P2。

| 项目 | 修复行为 | 验证 |
| --- | --- | --- |
| Wi-Fi 同步清理锁泄漏 | 未启动的进程也可安全清理；日志不再读取无效进程 ID，两把锁分别由 finally 保证释放。 | 实际清理方法注入未启动进程、首把锁释放异常。 |
| 完成录制被删除 | 完成编码后建立成品标记；发布失败保留 MP4，待保存及重启恢复可找到它，再次录制不能覆盖未保存成品。 | 目标冲突、保存重试、恢复扫描、禁止覆盖、正常发布。 |
| USB 恢复耗尽时清理竞争 | 清理加入 StopOperation，保持 Stopping 和桥接引用；投屏拆除等待清理，失败后保留所有权。重试或切换传输方式先清理旧桥接。 | 延迟清理、重复停止、采集拆除等待、清理异常后再次停止、原有绑定矩阵。 |
| USB 停止无法重试 | 区分输入活动与待清理资源；失败后停止仍可重入，并发停止共享任务，清理未成功时禁止重新启动。 | 在实际底层停止中注入异常，然后修复条件并再次调用。 |
| 多设备恢复封锁 | 有恢复封锁时继续枚举；原生层排除正在使用 USB 的设备，仅对其他设备进行新管理通道探测。 | 管理元数据策略与恢复库存回归，包括第二台设备、陈旧 Ready 和不可读通道。 |
| 解码候选链不完整 | 运行时解码失败与替补首次输入失败共用完整候选链；耗尽后终止。 | 硬件、DXVA 连续失败后软件成功；所有候选失败时有限终止；原生协议回归。 |
| 重启过早超时 | 使用单调时钟，最长等待 90 秒，覆盖激活、重枚举、8 秒握手、12 秒首帧及解码初始化；原生失败仍立即返回。 | 托管编译、采集状态与停止顺序回归；未做实机慢启动注入。 |
| HLS 异常误判 EOF | 仅退出码为零的桥接触发节目完成；非零退出进入已有恢复退避。释放进程不被视作成功。 | 实际 MediaEnded 处理路径分别注入退出码 0、7。 |
| 原始宿主反复启动 | Original 与 UxPlay 共用启动失败保护；启动调用失败退避 30 秒；手动应用允许重试，确认 Ready 前保留错误。 | Original 启动失败状态、重复轮询、手动重试及错误保留。 |
| DLNA 失败伪装就绪 | IPC 显式报告 DLNA 降级；每 5 秒独立重试，恢复后清除降级；AirPlay 和其 URL 播放命令继续可用。 | 实际宿主的 DLNA 端口占用后释放，验证降级、恢复、HTTP 服务及 AirPlay 只启动一次。 |
