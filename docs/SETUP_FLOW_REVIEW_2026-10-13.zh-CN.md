# 设置全流程优化与审查（2026-10-13）

本次审查覆盖设置助手的进入、恢复、设备发现、独立工具衔接、保存、取消、跳过和完成退出，以及驱动管理器与设备绑定器的相关刷新、弹窗和动画。审查采用代码阅读、隔离状态测试和实际 WPF 界面渲染。

最终审查未发现本次改动范围内尚未修复的阻塞问题。该结论不代表真实硬件安装与配对已经验收。

## 审查发现与修复

| 级别 | 问题与触发条件 | 最终处理 |
| --- | --- | --- |
| P1 | 绑定、重命名或删除弹窗期间，列表刷新或选中项变化可能使确认后的操作落到另一个设备档案。 | 弹窗前固定档案 ID，确认后继续使用原始目标；绑定再次确认设备存在和 AirPlay 就绪状态。 |
| P2 | 无线设置关闭绑定器后导入全部已保存的 AirPlay 档案，离线历史设备也加入当前向导。 | 工具返回选中的 AirPlay 身份，验证该档案后只采用所选设备；没有选择时保持未完成。 |
| P2 | AirPlay 添加窗口使用打开时的设备快照，新连接无法出现，断开的选项仍可确认。 | 实时观察设备集合与连接状态；断开时移除选项并禁用确认。 |
| P2 | 已有 USB、AirPlay、蓝牙绑定不能在当前步骤直接继续，导致重复打开工具。 | 当前绑定页面读取对应档案；有效绑定可继续，推进时保存当前步骤结果，删除的绑定不认可旧进度。 |
| P2 | 刷新反复替换下拉框数据源，易丢失未提交选择和焦点；状态变更未从设备项同步到窗口。 | 使用稳定的设备集合和增量更新，监听设备状态，合并界面更新并在断开时清除过期选择。 |
| P2 | 指定的设备尚未出现时会先选中其他档案，后续设备出现仍停留在错误目标。 | 保留待发现目标，在其档案出现时选中；用户明确改选其他档案后停止自动选择。 |
| P2 | 操作验证过程中采用了设备身份，但进度保存失败或操作取消后，内存仍保留未提交的设备队列。 | 操作开始时保存状态快照，失败或取消后回滚向导状态。独立工具已保存的真实绑定不受影响。 |
| P2 | 首次进度写入失败会在渲染页面前返回，留下空白设置窗口。 | 先渲染可操作的欢迎页，再保存首次进度；错误在页面内显示，可恢复后继续。 |
| P2 | 安装或扫描期间的 USB 插拔事件被丢弃，结束后列表可能过期。 | 保留待刷新标记，操作结束后合并刷新；窗口关闭后释放计时器与消息钩子。 |
| P2 | 没有 USB 或 AirPlay 身份的档案仍可点击蓝牙配置，但无法建立目标。 | 按有效身份启用蓝牙操作，缺少目标时显示原因。 |
| P3 | 过长状态文字挤压界面；重复动画与异步刷新缺少结束状态检查。 | 状态区限制高度并可悬停查看全文；验证重复动画保持原始透明度、停用时移除动画；关闭后的刷新不写回控件。 |

## 保持的流程约束

- 打开或重新打开助手时不执行“哪些设置未完成”的检查，也不展示检查汇总。
- 驱动安装和设备身份绑定仍由独立窗口完成；助手验证当前操作结果。
- 取消等待不结束独立驱动管理器进程。
- 用户可跳过步骤、恢复进度；跳过和关闭工具不等于配置成功。
- 窗口构造成功后才注册外部事件；关闭时退订设备与语言事件，清理待执行的界面更新。
