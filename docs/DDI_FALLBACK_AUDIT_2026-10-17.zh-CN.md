# DDI 回退链补充审查（2026-10-17）

基线为 `e542bd0`。本次沿 Cryptex → Personalized、Network Lockdown →
RemotePairing、无线 HID 缺失 → USB 准备及下载源切换检查，确认并修复以下遗漏。

| 遗漏 | 触发条件与影响 | 修复 |
| --- | --- | --- |
| 已成功的镜像回退没有保留 | iOS 27 在 Cryptex 失败后通过 Personalized 准备成功；后续 HID/RSD 重试又运行原 Cryptex 路径，重复失败并消耗总期限 | 仅在实际复用/挂载验证成功后记住本会话的 Personalized 选择；重试仍查询镜像 inventory，失败或取消不提交路线选择 |
| 旧 iOS 的无线恢复使用 Network 镜像服务 | Network Lockdown 可连接，但不提供镜像服务或 HID；原恢复仅对 Cryptex 走 USB，旧系统可能在 Network 连接上刷新镜像或直接重复 HID | 无线 HID 缺失时统一通过同一 UDID 的 USB 准备镜像，再重建无线会话；控制模式保持无线 |
| Network 镜像检查挡住可用控制路径 | 已有可用镜像/HID，但 Network 镜像服务返回不可用，启动在探测控制隧道前结束 | 仅对无线的镜像服务不可用延后检查，先验证实际控制/HID；确实缺少 HID 才请求 USB 准备 |
| 查询阶段设备错误未分类 | 服务打开成功后，真实 SDK 的 LookupImage 返回 InvalidService，原样抛出而无法进入上述回退 | inventory 边界也使用已有设备错误分类；保留原异常作为 cause |
| HTTP 200 的无效内容没有备用源 | raw 源返回同长度坏内容、截断文件或超大响应；代码只对 HTTP 错误尝试 API | 校验失败也尝试同一固定 revision 的 GitHub API；备用源仍须通过全部大小、哈希和 manifest 校验 |

前三项属于镜像与无线准备路线；最后两项分别补齐其错误分类和资源下载条件。

## 保留的失败条件

锁定、信任、身份不符、断连、超时与 Apple 签名网络错误不会因本修复被当作镜像
兼容问题。无线选择不会自动改成 USB 控制；USB 仅用于明确需要的镜像准备。
实际 HID 和触控 surface 检查仍是报告 ready 的必要条件。

已安装 Cryptex 但不提供 HID 时，仍保留镜像并在有限次数的重新发现后报告失败。
这里没有引入自动卸载、nonce 变更或未经设备验证的成功状态。
本轮未使用受影响用户的实机或 Apple 签名服务，因此不能据此确认最初几位用户的
共同根因，也不能保证其他系统版本及设备均无错误。
